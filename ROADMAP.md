## Next action

Phase 2 Tasks 1-4 (NATS infrastructure + subject/message contract; `nodes`/`containers` migration + repositories; worker node registration + heartbeat over NATS; worker NATS assignment subscription) are done — see the Phase 2 row above. Next: Task 5, the scheduler service (`services/scheduler`, new binary) — node registry (consumes register/heartbeat, upserts `nodes`, marks unreachable on heartbeat timeout) plus filter-then-score placement (consumes `placement.requested`, writes a `containers` row, publishes `node.<id>.assign` onto the winning node). This is the first task that depends on both Task 2's repositories and Task 4's assign/status contract now being done on the worker side.

## How to update this file

- Flip a phase to 🟨 when its first task starts, ✅ only when its exit criteria (`ARCHITECTURE.md` §10) actually pass.
- Add a one-line note on anything that deviated from the written plan — if a phase's actual implementation diverges from `ARCHITECTURE.md` or its ADRs, update those documents in the same change, don't just note the drift here and move on.
